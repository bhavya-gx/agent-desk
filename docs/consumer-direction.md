# Agent Desk: everyday-person direction

Working product brief following the owner's November 11, 2026 audience change. Visual identity is pending review of [three previews](visual-directions.md). The existing application remains a local technical pilot.

## One sentence

**One place for your AI helpers and everyday tasks.**

## Who it is for

People already trying one or more AI tools for life, work, learning, and personal projects. They want less repeated explaining and a clear place to return to their tasks. They should not need to understand agent orchestration, company structures, APIs, or a command line to use the eventual product.

“Everyday people” is the audience direction; the first practical group to validate with is individuals who already use an AI assistant and regularly lose track of requests or results. A universal audience claim would be premature before those workflows work well.

## The job

Capture what I need, give it to an appropriate helper, preserve the relevant details, and bring the result back so I can decide what happens next.

## From the original concept

| Original framing          | Personal framing                          | What still matters underneath                                     |
| ------------------------- | ----------------------------------------- | ----------------------------------------------------------------- |
| Client Desks              | My spaces: home, work, learning, projects | Keep context and account identity separate.                       |
| Results Inbox             | Ready for you                             | Show an actual result, not just a successful run.                 |
| Work-triggered Agents     | Help when there is something to do        | Avoid pointless model calls and explain usage.                    |
| Contact/audience profiles | People and preferences relevant to a task | Carry necessary details without exposing unrelated personal data. |
| Operator dashboard        | Today                                     | Show the next useful action before system details.                |

## First experience to build after choosing the design

1. Start with one personal space and an example task.
2. Connect one supported existing helper through an understandable, tested setup.
3. Write a request in ordinary language; suggest relevant context without requiring six form fields.
4. Preview what will be shared and which connected account will be used.
5. Bring back the draft or result, with a clear question if something is missing.
6. Let the person review it and explicitly authorize consequential external actions where needed.

No provider integration is implied by a helper illustration. Existing subscriptions do not automatically authorize API access or make usage free. The initial pilot's command-line setup and manually configured connector are not yet a consumer-ready onboarding flow.

## Voice

Plain, reassuring, specific. Say “A draft is ready” or “Which account should I use?” Show what happened and what is still waiting. Avoid “deploy a workforce,” “hire a CEO,” “orchestrate,” and claims that everything happens automatically.

## Design decision still open

Focus emphasizes a single next step. Color makes everyday use cases visible. Calm provides a familiar planner. The recommendation is Color for approachability, subject to the owner's selection and a small first-use study. The current one-page Word brief will be refreshed with the selected direction before it is treated as final.
