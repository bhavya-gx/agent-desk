# Every folder and file explained

This is the owner's guide to the repository. A **repository** is the project plus its recorded changes. A **commit** is a saved version. A **push** publishes those saved changes to GitHub. The repository is public; runtime data is local.

## Folders

| Folder | Purpose | Why it exists |
| --- | --- | --- |
| `app/` | Application code. | Keeps behavior separate from documentation and examples. |
| `app/web/` | The browser interface. | Contains what you see and click. |
| `skills/` | Reusable agent instructions. | Lets agents learn the workflow without duplicating the database. |
| `skills/brand-workspace/` | The portable Claude skill. | This is the folder copied into a compatible host's skills directory. |
| `skills/brand-workspace/scripts/` | The skill's API helper. | Gives the skill a reliable way to read and change tasks. |
| `examples/` | Public fictional configuration. | Lets anyone try the app without real client data. |
| `tests/` | Automated behavior checks. | Catches broken boundaries and task transitions before release. |
| `docs/` | Product, setup, brand, and owner documentation. | Explains both the intention and what currently works. |
| `scripts/` | Optional authoring utilities. | Rebuilds the brand document from editable text. |
| `.github/` | GitHub configuration. | Connects the repository to automated checks. |
| `.github/workflows/` | Automation definitions. | Runs tests on pushes and pull requests. |
| `.git/` | Git's local history and settings. | Created by Git. It is not an application folder or a place to edit manually. |
| `.local/` | Generated private database and access file. | Created by `init`, ignored by Git, never part of the published source. |
| `private/` | Optional private configuration and task JSON files. | Ignored by Git; created when you set up real records. |
| `__pycache__/` | Python's generated bytecode caches. | Automatically created while running Python, ignored by Git. |

## Root files

| File | What it does |
| --- | --- |
| `README.md` | The public front door: product purpose, status, setup, tests, and documentation links. |
| `LICENSE` | Grants permission to use, modify, and redistribute the original code under MIT terms. |
| `.gitignore` | Prevents databases, credentials, local caches, and private files from being accidentally added by ordinary Git commands. It is not encryption. |
| `AGENTS.md` | Instructions for coding agents working on this repository: preserve boundaries, test changes, and keep explanations current. |
| `CONTRIBUTING.md` | How other people can propose changes. |
| `SECURITY.md` | The local deployment boundary and how to report a potential vulnerability. |
| `requirements-docs.txt` | Optional dependency for regenerating Word output. The running app needs none of these packages. |

## Application files

| File | What it does |
| --- | --- |
| `app/__init__.py` | Marks `app` as a Python package so `python3 -m app.server` works. |
| `app/store.py` | Validates records, stores tasks, enforces brand/agent access, manages transitions, and appends activity events. Transactions prevent competing claims from both succeeding. |
| `app/server.py` | Initializes the database/tokens; starts the local HTTP server; signs the owner in; serves pages and authenticated API routes. |
| `app/paperclip.py` | Builds a handoff preview, checks the remote agent's company, and sends an issue to Paperclip. Reserves uncertain sends to avoid duplicate work. |
| `app/web/index.html` | The page structure: sign-in, brand switcher, board, creation form, and task details. |
| `app/web/style.css` | Typography, spacing, colors, responsive layout, and visible focus styles. |
| `app/web/app.js` | Loads records, switches brands, submits forms, opens task details, and renders history. Escapes stored text before inserting it into HTML. |

| File | What it does |
| --- | --- |

| `skills/brand-workspace/scripts/workspace.py` | A standalone command-line client. Reads the service URL and scoped token from environment variables and calls the API. |

## Private generated files

`.local/workspace.db` stores the brand records, tasks, and activity events. SQLite may also create `workspace.db-wal` and `workspace.db-shm` while running; these support consistent database writes. `.local/access.json` stores access tokens and has owner-only file permissions on supported operating systems. None is uploaded to GitHub.

## The outer chat workspace

The `outputs/brand-agent-workspace/` folder is this repository. The surrounding chat's `work/` folder contains temporary rendering and verification files. These are outside the repository. The surrounding `outputs/` folder can also hold a preview screenshot. Only reviewed project files are committed; the outer chat workspace is not pushed.

The local folder keeps its original name to preserve existing paths. The public repository is `bhavya-gx/agent-desk`. The skill folder and environment variables also retain their original technical names so existing setup commands keep working.
